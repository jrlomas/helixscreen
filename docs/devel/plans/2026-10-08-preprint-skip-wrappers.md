# Pre-print skip toggles through Klipper command wrappers

**Status:** plan, approved direction 2026-10-08 (Preston). Branch `feature/preprint-skip-wrappers`.

## Goal

Let a user skip bed mesh, QGL and Z-tilt for one print from the print detail panel on a
printer whose PRINT_START runs them unconditionally, **without editing the user's
PRINT_START or any other user-owned config**. The removed PRINT_START rewriter (#1233)
did that by editing the macro and was dropped for it; this design never touches it.

## Decisions (Preston, 2026-10-08)

| Question | Decision |
|---|---|
| Skipping the bed mesh uses which mesh? | **Keep the active mesh.** Offer the skip only while a mesh is loaded (`bed_mesh.probed_matrix` non-empty); skipping leaves it in place. |
| How are QGL / Z-tilt skips gated? | **Offer only while `applied` is true** (a level ran since the last motors-off). Edge cases (`retries=0`, custom idle gcode) are the user's call. |
| Where do the wrappers live? | **A separate generated file**, `helix_skips.cfg`, written per printer, plus one `[include]` line. |
| How is it turned on? | **Automatically with the helper macros**: install and update of `helix_macros.cfg` also stage `helix_skips.cfg`. |

## Klipper facts the design rests on

Researched in Klipper master and Kalico (`~/Code/Printing/kalico` @29e8ef41), 2026-10-08.

- `gcode_macro` `rename_existing` on a built-in pops the handler at `klippy:connect` and
  re-registers it under the new name (`gcode_macro.py#GCodeMacro.handle_connect`).
  `{rawparams}` passes the original parameters through verbatim (`PROFILE=`, `ADAPTIVE=1`,
  `METHOD=`). ADAPTIVE reads `exclude_object` status, unaffected by the wrapper.
- Beacon, Cartographer (v1 and v2) and Creality prtouch replace these commands at **config
  load**; the macro rename runs later at connect, so the wrapper layers over them cleanly
  regardless of include order. Python re-registration therefore does not block wrapping.
- **Same-named `[gcode_macro X]` sections in two files merge silently**, later file wins per
  option (`configfile._create_fileconfig`, `strict=False`). This is the one real hazard: a
  user macro of the same name is merged with ours. A rename target that already exists makes
  Klipper refuse to start (`register_command` raises).
- `;` starts a comment in config and in gcode scripts: every command in a wrapper body is on
  its own line.
- `quad_gantry_level.applied` / `z_tilt.applied` reset only on `stepper_enable:motor_off`
  (M84/M18, default idle_timeout) and restart; G28 does not reset them. Kalico's
  `z_tilt_ng` has its own `applied`.
- An ADAPTIVE mesh has an empty `profile_name` but a populated `probed_matrix`.
- Moonraker scripts run FIFO under Klipper's gcode mutex. The pre-start block
  (`PrintPreparationManager::start_print`, `execute_gcode` with `continue_print_start` in its
  success callback) completes before `print.start` is sent, so flags set there are in place
  when the file's START_PRINT runs.

Fleet measurement (2026-10-08, 6 live printers): **0** define a `gcode_macro` for any of the
three commands. Bed mesh is wrappable on 5/6 (K2 Plus re-registers it in Python, which
layering handles), QGL on 1 (Voron), Z-tilt on 1 (K2 Plus). The Centauri Carbon (COSMOS)
defines `BED_MESH_CALIBRATE` as a macro and gets no wrapper. The mock's generic and Creator 5
Pro personas publish `gcode_macro BED_MESH_CALIBRATE`.

## Design

### 1. The generated file

`helix_skips.cfg`, generated from what the printer has:

```
# helix_skips v1 - generated by HelixScreen; wraps: bed_mesh,qgl
[gcode_macro _HELIX_PREP]
variable_run_bed_mesh: 1
variable_run_qgl: 1
variable_run_z_tilt: 1
gcode:
    SET_GCODE_VARIABLE MACRO=_HELIX_PREP VARIABLE=run_bed_mesh VALUE=1
    SET_GCODE_VARIABLE MACRO=_HELIX_PREP VARIABLE=run_qgl VALUE=1
    SET_GCODE_VARIABLE MACRO=_HELIX_PREP VARIABLE=run_z_tilt VALUE=1

[gcode_macro BED_MESH_CALIBRATE]
rename_existing: _HELIX_BASE_BED_MESH_CALIBRATE
description: Bed mesh calibrate (HelixScreen can skip it for one print)
gcode:
    {% if printer["gcode_macro _HELIX_PREP"].run_bed_mesh|int == 0 %}
        SET_GCODE_VARIABLE MACRO=_HELIX_PREP VARIABLE=run_bed_mesh VALUE=1
        {action_respond_info("HelixScreen: bed mesh skipped, keeping the active mesh")}
    {% else %}
        _HELIX_BASE_BED_MESH_CALIBRATE {rawparams}
    {% endif %}

[gcode_macro BED_MESH_CLEAR]      # only when BED_MESH_CALIBRATE is wrapped
rename_existing: _HELIX_BASE_BED_MESH_CLEAR
gcode:
    {% if printer["gcode_macro _HELIX_PREP"].run_bed_mesh|int == 1 %}
        _HELIX_BASE_BED_MESH_CLEAR {rawparams}
    {% endif %}
```

`QUAD_GANTRY_LEVEL` and `Z_TILT_ADJUST` follow the BED_MESH_CALIBRATE shape. `_HELIX_PREP`
with no arguments resets every flag.

- **Flag semantics:** `run_X = 1` means run. That matches the existing `PreStartGcode`
  template, where `{value}` is 1 for an enabled toggle. Toggle ON (the default) sends `VALUE=1`,
  a no-op; toggle OFF sends `VALUE=0`.
- **One-shot:** the wrapper restores `run_X = 1` the moment it consumes a skip.
  `BED_MESH_CLEAR` does not consume, because PRINT_START typically clears before it calibrates
  (the Voron's does), and clearing would throw away the mesh the skip means to keep.
- **Leftover flags** are reset by HelixScreen (section 4), and by any Klipper restart.

### 2. Generator and conflict check: one pure module

`include/preprint_skip_wrappers.h` + `src/printer/preprint_skip_wrappers.cpp`, no LVGL and no I/O:

```cpp
namespace helix::skip_wrappers {
enum class Op { BedMesh, Qgl, ZTilt };
struct PrinterFacts {
    std::set<std::string> objects;          // lower-case objects/list names
    std::set<std::string> macro_sections;   // lower-case "gcode_macro x" keys from configfile.settings
    std::set<std::string> commands;         // upper-case registered commands (gcode/help)
};
std::vector<Op> wrappable(const PrinterFacts&);           // empty -> no file
std::string generate(const std::vector<Op>&);              // the file text, versioned header
bool ours_intact(const nlohmann::json& configfile_settings, Op); // section equals what generate() wrote
std::string command_for(Op);                               // "BED_MESH_CALIBRATE" ...
std::string flag_for(Op);                                  // "run_bed_mesh" ...
}
```

`wrappable(f)` includes an Op only when **all** of these hold:

- its built-in object exists: `bed_mesh`; `quad_gantry_level`; or `z_tilt` / `z_tilt_ng`;
- no `gcode_macro <command>` section exists, case-insensitive, other than one `ours_intact()`
  recognizes;
- neither `_HELIX_BASE_<command>` nor (for bed mesh) `_HELIX_BASE_BED_MESH_CLEAR` is
  already a registered command.

### 3. Install, update, uninstall, rollback

`MacroManager` stages the second file next to `helix_macros.cfg`. Extend the existing helpers
rather than adding twins:

- `add_include_to_config` / `remove_include_from_config` take the filename.
- `upload_macro_file` takes the name and content.

Install and update stage `helix_skips.cfg` (when `wrappable()` is non-empty) and its include,
and the existing `request_restart()` applies both. No new restart policy: it is never called
during a print. Uninstall removes both files and both includes.

**Rollback:** after a restart that introduced or changed `helix_skips.cfg`, if Klippy does
not reach `ready` within the existing restart window, HelixScreen deletes `helix_skips.cfg`,
removes its include, restarts Klipper once more and shows a toast. Moonraker stays up through
a Klipper config error, so this needs no SSH. Rollback runs at most once per staging and never
touches `helix_macros.cfg`.

**Conflict after the fact:** at each discovery, if the file is installed but
`ours_intact()` fails for a wrapped Op (the user later added a same-named macro, which merged
with ours), HelixScreen hides that Op's toggle, logs a warning, regenerates the file without
the Op, and raises the existing restart-pending offer.

### 4. Options, gating, and the card

- **Status:** subscribe `quad_gantry_level: ["applied"]`, `z_tilt: ["applied"]`,
  `z_tilt_ng: ["applied"]` when present. `bed_mesh.probed_matrix` is already subscribed.
- **Options:** for each wrapped Op that the print will actually run (the PRINT_START
  analysis found it, controllable or not, or the file scan has it), synthesize a
  `PreStartGcode` option:
  - `id` = `bed_mesh` / `qgl` / `z_tilt`, with the existing labels and default ON;
  - template `SET_GCODE_VARIABLE MACRO=_HELIX_PREP VARIABLE=run_<x> VALUE={value}`,
    `emit_when_disabled = true`, `requires_macro = "_HELIX_PREP"`.
- **Precedence:** a database option or a macro skip parameter for the same capability
  wins (`declares_capability`). The wrapper option is the fallback, never a second row.
- **Gate:**
  - bed mesh: shown only while `probed_matrix` is non-empty;
  - QGL / Z-tilt: shown only while the matching `applied` is true.

  When the gate closes, the row hides and its line is not emitted.
- **No plugin needed:** these are `PreStartGcode` rows. The card aggregate must count
  plugin-free rows separately from plugin-gated macro rows. Split
  `PrinterState::set_macro_option_count` into plugin-gated and plugin-free counts:
  `has_any = framework > 0 || timelapse || plugin_free > 0 || (plugin && plugin_gated > 0)`.
- **Reset:** when a print reaches a terminal state (complete, cancelled, error), and on
  connect while idle, HelixScreen sends `_HELIX_PREP` if the file is installed and any
  `run_*` reads 0. Subscribe `gcode_macro _HELIX_PREP` for the three variables.

### 5. HelixScreen's own detection

Every site that infers something from `gcode_macro BED_MESH_CALIBRATE` (or the other two)
must not count ours. `skip_wrappers::ours_intact()` is the one test. Audit
`src/printer/printer_discovery*.cpp`, the bed-mesh-self-prepares path, and the mock personas.

### 6. Mock

- A persona flag that omits `gcode_macro BED_MESH_CALIBRATE`, so wrappers are wrappable under
  `--test`.
- The mock's gcode handler honors `_HELIX_PREP` variables: a skipped
  `BED_MESH_CALIBRATE` / `QUAD_GANTRY_LEVEL` / `Z_TILT_ADJUST` returns at once and consumes the flag.
- `SET_GCODE_VARIABLE` on `_HELIX_PREP` updates the published status.

## Tests (each must fail with its feature removed)

| Area | Cases |
|---|---|
| `wrappable()` | Voron facts give {BedMesh, Qgl}; an existing `gcode_macro bed_mesh_calibrate` (any case) drops BedMesh; an existing `_HELIX_BASE_*` command drops it; `z_tilt_ng` counts as ZTilt; no `bed_mesh` object means no BedMesh; our own intact section does not count as a conflict |
| `generate()` | each command on its own line (no `;`); `{rawparams}` forwarded; BED_MESH_CLEAR wrapper present iff BedMesh; header lists the wrapped Ops; empty Op list gives an empty string |
| `ours_intact()` | identical settings true; a merged section with a foreign `gcode` or `rename_existing` false |
| MacroManager | install stages both files and both includes in order; update regenerates; uninstall removes both; no `wrappable()` means no second file or include |
| Rollback | Klippy `error` after a restart that staged the file triggers delete, un-include and one restart; a second failure does not loop; `helix_macros.cfg` untouched |
| Options | a wrapped and analyzed op gives a row; a DB or macro-param option for the same capability suppresses it; gate closed hides the row and emits nothing; toggle OFF emits `VALUE=0`; ON emits `VALUE=1` |
| Card | plugin absent plus wrapper rows shows the card; plugin absent plus only macro-param rows hides it |
| Reset | terminal state with a `run_*` of 0 sends `_HELIX_PREP`; all 1 sends nothing |
| Mock | skipped BED_MESH_CALIBRATE does not run and restores the flag |
| bats | none unless `install.sh` changes (it does not) |

`make mutate-diff` once over the branch at the end; mutations named in the last commit.

## Device verification (Voron .112, after its current print; one session on the device)

1. Install or update the helper macros from Advanced. Confirm `helix_skips.cfg` holds
   BED_MESH_CALIBRATE, BED_MESH_CLEAR and QUAD_GANTRY_LEVEL wrappers, Klipper comes back ready,
   and `BED_MESH_CALIBRATE` help reads ours.
2. A home and QGL from the UI sets `applied`. Run a mesh. Open a file: the QGL and bed mesh
   toggles show without the plugin.
3. Toggle both OFF and print. The console shows both "skipped" lines, the mesh is unchanged,
   and both flags read 1 afterwards. Confirm every gcode command, home and heat with Preston
   before it is sent.
4. Cancel a print with a skip set before START_PRINT reaches the op: the flag resets.

## Constraints

- Never write to a user-owned file other than the single `[include helix_skips.cfg]` line
  (same mechanism as `helix_macros.cfg`, which already backs up printer.cfg).
- Never restart Klipper during a print.
- Vendor names stay out of generic code: the capability lives in `skip_wrappers`.
- Nozzle clean and purge are out of scope. Their commands are user macros, and wrapping one
  means a same-named section that merges with theirs.
